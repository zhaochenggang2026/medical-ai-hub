完整链路（PDF → 结构化数据）

Step1：PDF 转图片

import fitz  # PyMuPDF

doc = fitz.open("检验报告.pdf")
for i, page in enumerate(doc):
    pix = page.get_pixmap(dpi=200)  # 200dpi 够清晰
    pix.save(f"page_{i}.png")

Step2：OCR 识别

from paddleocr import PaddleOCR

ocr = PaddleOCR(use_angle_cls=True, lang='ch')  # 中文

result = ocr.ocr("page_0.png", cls=True)
# 输出：每行文本 + 位置 + 置信度
for line in result[0]:
    text = line[1][0]
    conf = line[1][1]
    print(f"{conf:.2f} | {text}")

Step3：结构化提取（关键）

OCR 出来的是「一行行文字」，要变成「字段:值」：

import re

def extract_value(text_lines, keyword):
    """从OCR结果中找关键词后面的数值"""
    for text in text_lines:
        if keyword in text:
            # 例："血糖 5.6 mmol/L" → 提取 5.6
            m = re.search(r'([\d.]+)\s*(mmol/L|mg/dL)', text)
            if m:
                return m.group(1), m.group(2)
    return None, None

# 示例
glucose, unit = extract_value(all_texts, "血糖")
print(f"血糖: {glucose} {unit}")

嵌入式设备怎么用（重点）

PaddleOCR 模型不算大（~10MB），但跑在 MCU 上不现实。医疗设备的实际做法：

方案A（本地工作站）：
  电脑/工控机 → 跑完整 PaddleOCR → 解析报告

方案B（边缘盒子）：
  RK3588/树莓派 → PaddleOCR（ARM 版）
  → 配合打印机/扫描仪做「报告录入一体机」

方案C（手机端）：
  PaddleOCR 有移动端方案（PaddleOCR-Lite）
  → 拍照识别 → 自动录入

推荐：方案B（边缘盒子）最适合医疗设备集成

🟠

但是

三个坑提前说：

1. **版面复杂会乱。** 多表格、多栏报告，需要先做版面分析（PaddleOCR 支持 PP-Structure 版面解析）。

2. **数值校验必须做。** OCR 识别「5.6」可能读成「5.8」。医疗数据要加范围校验（血糖正常范围 3.9~6.1），超范围报警提示人工核对。

3. **合规问题。** 如果做成医疗器械的「检验数据自动录入」功能，涉及医疗数据处理，要按软件合规走（IEC 62304）。作为内部工具则无碍。

**一句话：** OCR 让「纸质报告 → 电子数据」自动化，医疗场景价值巨大——但数值校验和合规边界别忽略。
