用AI搭一个「医疗器械法规问答助手」难吗？

我花了一个周末，用通义千问搭了一个能查 GB 9706、ISO 14971、IEC 62304 条款的问答助手。不吹牛，从0到1的完整路径给你，你也能搭。

🟠

先想清楚：要搭什么

目标：一个能回答「XX标准对XX的要求」的助手。

难点：大模型不知道标准全文，会瞎编（幻觉）。所以不能直接问，要「检索+生成」——先搜到标准条款，再让模型基于条款回答。这叫 **RAG（检索增强生成）**。

🟠

第1步：准备知识库（半天）

把你手头的标准文档转成可检索的文本：

1. 把 PDF/Word 标准转成纯文本

2. 分段（每段 500~1000 字，带标题）

3. 每段加标签（标准名+条款号）

示例分段：
[GB 9706.1-2020 | 第5.3节] 关于漏电流的要求：...
[ISO 14971 | 第4.2节] 风险管理计划应包含：...

🟠

第2步：向量化+建索引（2小时）

用 Embedding 模型把文本转成向量，存入向量数据库：

from dashscope import TextEmbedding

# 用通义千问的向量模型
resp = TextEmbedding.call(
    model='text-embedding-v3',
    input='GB 9706.1 漏电流要求'
)
vector = resp.output['embeddings'][0]['embedding']

向量库可以用轻量的 ChromaDB（本地运行，免费）：

• 每条标准段落 → 一个向量

• 查询时：问题转向量 → 找最相似的 3~5 段

🟠

第3步：搭问答逻辑（2小时）

核心流程：

用户提问 → 向量检索（找相关条款）
→ 拼 Prompt（条款+问题）→ 通义千问生成回答

from dashscope import Generation

def ask_standard(question):
    # 1. 检索相关条款
    hits = vector_db.search(question, top_k=5)
    context = "\n".join(h.text for h in hits)
    
    # 2. 拼 Prompt（关键：让模型基于条款回答，别瞎编）
    prompt = f"""你是医疗器械法规助手。请基于以下标准条款回答，不要编造。
    
标准条款：
{context}

问题：{question}

回答："""
    
    # 3. 生成
    resp = Generation.call(model='qwen-plus', prompt=prompt)
    return resp.output.text

**关键技巧：** 在 Prompt 里明确「基于以下条款回答，不要编造」——这是抑制幻觉的核心。

🟠

第4步：加界面（可选，1天）

用 Streamlit/Gradio 加个网页界面：

st.title("医疗器械法规问答助手")

    st.write(ask_standard(q))

但是

三个现实提醒：

1. **知识库要维护。** 标准会更新，你的向量库要跟着更新。加个「更新日期」字段。

2. **回答要人工核验。** RAG 大大减少幻觉，但仍有编造风险。合规场景（注册文档）必须人工复核引用。

3. **这只是助手。** 它帮你快速查条款、出初稿，但「审评老师会怎么看」这种判断，还是要你。

这套东西搭好以后，你查标准的时间能省 80%。而且是本地数据（合规友好），以后还可以接 MCP 协议做成公司内部的 Agent 工具——就像我给你的 Spring AI 平台那样。
