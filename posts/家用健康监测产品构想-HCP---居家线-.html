家用健康监测产品构想（HCP · 居家线）

> 定位：**家庭健康监测（非注册类）**——居家健康感知 + 自然语言交互 + 家人联动；不做诊断/治疗。

> 与平台线关系：复用 [[产品线统一平台规划_NCP-2|NCP-2]] 的信号前端与报警设计思想，**交互/决策层改用 [[ESP-Claw_乐鑫设备端AI-Agent框架|ESP-Claw]]（ESP32-S31）**，形成「院内 NCP / 居家 HCP」两条线。

> 命名草案：**HCP-100**（Home Care Platform）。

一、定位与边界

• **做**：居家体征采集、异常本地告警、家人远程感知、自然语言查询与陪伴交互。

• **不做**：诊断结论、治疗干预、剂量控制——即**不进入注册器械范畴**，规避"算法锁定/证据链"负担。

• **与 NCP 的关系**：HCP 是 NCP-2 统一平台的**居家延伸**——共用前端信号链与报警设计思路；交互/决策层引入 ESP-Claw，走"设备端 Agent"路线。

二、目标用户与场景

• 用户：慢病老人、术后居家康复、独居老人；核心付费/使用方常是**异地子女**。

• 典型闭环：日常体征采集 → **本地规则判异常** → 本地告警 → **微信/飞书通知家人** → 家人/老人用自然语言追问（"我妈昨晚血氧怎么样"）。

三、产品形态（建议）

• **台式 / 床边主机**（ESP32-S31 + 小屏）：插电为主，承载 Agent 与主交互——**这是 ESP-Claw 最顺的形态**。

• **传感子模块**：血氧/PPG、心电（电极）、体温、体重（可选睡眠）。

• **家人端**：微信 / 飞书（直接复用 ESP-Claw 的 IM 能力，零新 App）。

• **可选穿戴件**：单独选低功耗芯片，**降级为本地规则**（不强上 LLM）。

四、系统架构

传感层(PPG/ECG/体温/体重)
   │
采集与调理（可复用 NCP-2 的 ADS129x 前端 + 桥路/NTC）
   │
ESP32-S31  ·  本地事件总线
   ├─ Lua 规则引擎：阈值告警 / 联动 / 记录   → 确定性、离线可执行
   ├─ ESP-Claw Agent：LLM 决策 + 固化 Lua    → 自然语言交互（在线）
   │     └─ 多 Agent：监护 Agent + 对话 Agent
   └─ MCP：设备能力对外暴露（Server）+ 调外部服务（Client）
   │
云/家人端：微信 · 飞书 · 可选云平台

• **云边协同**：**本地兜底**（Lua 规则离线跑）+ **在线增强**（LLM 交互）。

五、关键设计取舍

| 维度 | 取舍 |

|------|------|

| 确定性 vs 灵活 | 告警/联动**固化成本地 Lua**（不靠模型临场）；模糊需求交给 LLM |

| 隐私 | **健康数据本地优先**；云端 LLM 调用**脱敏**（非注册也受《个保法》约束） |

| 功耗/形态 | 主机**插电**；穿戴单列低功耗方案 |

| 可靠性/QC | 关键阈值逻辑自研写死，产品责任自负（早期框架） |

六、原型路径（3 阶段）

• **P0 通路验证**：一块 ESP32-S31 / 面包板 → 浏览器**在线烧录 ESP-Claw** → 跑通「模拟传感器事件 → 本地 Lua 规则 → 微信/飞书通知」。**先不接真传感器**，验证"事件→告警→家人端"闭环。

• **P1 最小闭环**：接真实传感（如 MAX30102 PPG / ADS129x ECG 子板）→ 阈值告警 + 自然语言问答（"昨晚血氧怎么样"）。

• **P2 小批量**：结构/电源/外壳（宋超）；非注册也要过 **EMC / 电气安全 / 个保法** 评估。

七、选型 / BOM 雏形

• **主控**：ESP32-S31（双核 RISC-V 多协议 SoC，面向 AIoT/智能家居中枢；**≥8MB Flash + ≥8MB PSRAM** 起，跑 ESP-Claw）。

• **传感**：MAX3010x（PPG/血氧）；ADS129x（ECG/EEG，可复用 [[产品线统一平台规划_NCP-2|NCP-2]] 前端）；NTC/SHT（体温）；压力/称重（体重）。

• **交互**：LVGL 小屏（复用 NCP 的 GUI 思路）+ 微信/飞书。

• **电源**：插电 + 后备锂电。

八、风险与对策

| 风险 | 对策 |

|------|------|

| ESP-Claw 早期框架、版本迭代快 | 原型阶段**锁定版本**；关键逻辑自研，不依赖生成 |

| 联网依赖（LLM 用 API） | 本地兜底 + 在线增强，断网仍能告警 |

| 隐私 / 个保法 | 数据本地优先、云调用脱敏、明确授权 |

| 功耗（S3/P4 + PSRAM 较费电） | 主机插电；穿戴另择低功耗芯片 |

| 供应链 | ESP32-S31 国产、供货稳（呼应 [[STM32_AI应用笔记|国产化]]方向） |

九、与 NCP 平台的协同

• **复用（NCP-2 已有）**：信号前端（ADS129x/桥路）、报警引擎设计思想、LVGL GUI、外壳结构。

• **新增（居家线）**：ESP-Claw 交互/决策层、IM 家人联动、MCP 能力暴露。

• **供应链统一**：ADS129x、电源、连接器等与院内线共用，摊薄成本。
